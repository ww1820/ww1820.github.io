VS Code Remote-SSH 卡在"正在下载 VS Code 服务器"：手动安装 ​

用 VS Code 的 Remote-SSH 连接服务器时，如果状态栏长时间停留在「正在下载 VS Code 服务器（Setting up SSH Host xx: Downloading VS Code Server）」，最常见的原因是服务器无法访问外网——VS Code 需要从 update.code.visualstudio.com 下载一个与本地版本匹配的 server 端组件，这个下载是在服务器上执行的，服务器不通外网就永远卡住。解决办法是在本地下载好对应组件手动传上去。本文记录完整步骤与两个关键细节。

手动安装步骤 ​

1. 获取本地 VS Code 的 commit id ​

VS Code 每个版本的 server 组件与 commit 哈希一一对应，所以先要拿到本地客户端的 commit id：

  • 菜单 Help → About，查看 Commit 行；或
  • 命令行执行 code --version，第二行即 commit 哈希。

2. 在本地下载对应的 server 包 ​

浏览器直接访问以下地址即可触发下载（把 ${commit id} 替换为上一步的值）：

https://update.code.visualstudio.com/commit:${commit id}/server-linux-x64/stable
1

服务器是 arm64 架构时，把 server-linux-x64 换成 server-linux-arm64。

3. 传到服务器并解压 ​

bash
scp vscode-server-linux-x64.tar.gz user@server:~/
ssh user@server
mkdir -p ~/.vscode-server/bin/${commit id}
tar -zxf ~/vscode-server-linux-x64.tar.gz --strip-components=1 -C ~/.vscode-server/bin/${commit id}
1
2
3
4

完成后本地重新连接，VS Code 检测到对应 commit 的 server 已就位就不再下载。

两个关键细节 ​

解压必须去掉顶层目录 ​

tar 包解压出来是 vscode-server-linux-x64/ 目录，而 VS Code 期望的布局是 ~/.vscode-server/bin/${commit id}/bin/ 下直接有可执行文件。如果不加 --strip-components=1，解压结果会多一层目录，server 启动脚本位置不对，连接照样失败。这是多数教程没讲清、实操最容易翻车的一步。

本地 VS Code 升级后要重新做 ​

commit id 随版本变化，本地 VS Code 一升级，服务器上旧 commit 的 server 就不再匹配，需要按新 commit id 重新下载放置。另外，VS Code 1.86 之后 server 安装流程引入了 CLI 组件与新的目录结构（~/.vscode-server/cli/servers/Stable-{commit}），若按上述步骤放好仍连不上，先检查服务器上是否存在这个新路径体系，再对照官方文档处理。

小结 ​

卡在下载服务器，本质是服务器侧出网受阻。手动安装的关键三点：commit id 要与本地版本精确匹配（Help → About 获取）、下载 URL 按架构选对变体、解压加 --strip-components=1 保证目录层级正确。步骤依据见 Stack Overflow 的离线安装讨论 与 Microsoft Learn 的手动安装步骤。若服务器只是网络慢而非完全不通，也可以只给服务器配置代理后让 VS Code 自动完成下载。
