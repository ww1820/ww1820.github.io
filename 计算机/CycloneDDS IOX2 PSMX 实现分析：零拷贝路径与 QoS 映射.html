CycloneDDS IOX2 PSMX 实现分析：零拷贝路径与 QoS 映射 ​

CycloneDDS 通过 PSMX（Publish-Subscribe Messaging eXtension）接口集成 iceoryx2，实现基于共享内存的零拷贝数据传输。这篇文章基于 CycloneDDS 源码（psmx_iox 模块），分析它的数据结构层次、固定/动态两类类型的不同写入路径、QoS 支持边界，以及运行时如何决定一条数据走共享内存还是网络。

架构总览 ​

核心实现分布在：

  • src/psmx_iox/src/psmx_iox2_impl.c — IOX2 PSMX 插件实现
  • src/core/ddsc/src/dds_write.c — DDS 写入路径（含序列化逻辑）
  • src/core/ddsc/src/dds_writer.c — Writer loan 管理

类型分类 含义 举例
FIXED_SIZE（memcpy-safe） 纯 POD 类型，无指针/动态成员 struct { int32_t x; double y; }
DYNAMIC（非 memcpy-safe） 含指针或变长成员 含 string、sequence、optional 的类型

两种类型在各环节的差异 ​

环节 FIXED_SIZE DYNAMIC
创建 IOX2 服务 按 type_variant 声明 payload 类型 同左

写入路径中的序列化 ​

序列化发生在 DDS 核心层（dds_write.c / dds_writer.c），而非 IOX2 插件内部。核心函数 dds_write_impl_psmxloan_serdata 按类型选择三条路径：

三条路径的关键函数对照：

函数 源文件 用途
dds_writer_psmx_loan_raw dds_writer.c memcpy-safe 类型：直接 memcpy 到共享内存
dds_write_impl_serialize_into_loan dds_write.c 动态类型快速路径：直接序列化到 loan
dds_writer_psmx_loan_from_serdata dds_writer.c 动态类型通用路径：从 serdata 拷贝 CDR 到 loan（size 减 4 字节 CDR 头）

sample_state 含义 何时设置

QoS 实现情况 ​

QoS 兼容性检查 ​

创建端点前，psmx_iox2_type_qos_supported 依次检查以下条件，任一不满足即返回 false，该端点回退到网络传输：

  1. 含 key 且未开启 support_keyed_topics → 拒绝；
  2. 仅主题级检查（endpoint_type 未设）→ 通过；
  3. 分区数大于 1 或含通配符 → 拒绝；
  4. Durability 不在 {VOLATILE, TRANSIENT_LOCAL} → 拒绝；
  5. Liveliness 非 AUTOMATIC → 拒绝；
  6. Deadline 非 INFINITY → 拒绝；
  7. IgnoreLocal 非 NONE → 拒绝。

已实现与未实现的 QoS 映射 ​

DDS QoS IOX2 实现 状态
Reliability BEST_EFFORT → DISCARD_SAMPLE；RELIABLE → BLOCK 已实现
Partition 主题名+分区名哈希 → 唯一 IOX2 服务名 已实现

Liveliness 仅允许 AUTOMATIC 仅默认值

IgnoreLocal 仅允许 NONE 仅默认值

完整写入流程 ​

投递方式决策矩阵 ​

写入时是否走 PSMX、是否还要序列化走 DDSI（网络），由运行时 reader 组合决定：

有 PSMX endpoint? 有网络 reader? 有本地非 PSMX reader? 投递方式
否 - - 仅 UDP（DDSI）
是 否 否 仅 PSMX（最优路径，可跳过序列化）
是 是 否 PSMX + UDP 双投递
是 否 是 PSMX + 本地 DDSI 投递
是 是 是 PSMX + UDP + 本地 DDSI

完整决策链路：

配置文件通过 <PubSubMessageExchange> 启用 PSMX 插件（如 iox2），但最终某条数据是否走共享内存，还取决于运行时匹配到的 reader 组合——纯 PSMX reader 场景才能拿到零序列化的最优路径。

配置参数 ​

IOX2 PSMX 插件通过 iox2_create_psmx 初始化，支持以下配置：

参数 默认值 说明
INSTANCE_NAME （必填） IOX2 域名，作为所有资源的前缀隔离不同域
LOCATOR 机器 ID 节点唯一标识符（32 字节十六进制）
LOGLEVEL fatal 日志级别
KEYED_TOPICS true 是否支持带 key 的主题
ALLOW_NONDISCOVERED_WRITERS false 是否接受未发现的写者的数据

支持的 PSMX 特性标记：DDS_PSMX_FEATURE_SHARED_MEMORY | DDS_PSMX_FEATURE_ZERO_COPY。

设计要点总结 ​

  1. 类型区分的核心标志：唯一起作用的是 DDS_DATA_TYPE_IS_MEMCPY_SAFE（bit 63），DDS_DATA_TYPE_CONTAINS_STRING 等标志已全部定义为 0（废弃）。
  2. 动态类型无法零拷贝用户数据：含 string/sequence 的类型内存不连续，必须先序列化为 CDR 字节流再写入共享内存，接收端也要反序列化。
  3. 固定类型真正零拷贝：memcpy-safe 类型直接把结构体 memcpy 进共享内存，接收端直接读原始结构体。
  4. QoS 不兼容时自动回退：type_qos_supported 返回 false 时，DDS 自动回退到网络传输路径，对用户透明。
  5. History 映射有已知问题：代码中 history 的映射被注释掉，注释说明会导致乱序接收和写阻塞。
