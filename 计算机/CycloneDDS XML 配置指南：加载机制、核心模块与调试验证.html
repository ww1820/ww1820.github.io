CycloneDDS XML 配置指南：加载机制、核心模块与调试验证 ​

CycloneDDS 采用基于 XML Schema（XSD）的配置文件机制，允许在不修改源代码、不重新编译的情况下，控制 DDS 运行时的网络行为、发现策略与性能参数。这篇文章梳理配置的加载机制、常用模块的写法，以及配置不生效时的验证与排查方法。

配置文件加载机制 ​

环境变量 CYCLONEDDS_URI（主要入口） ​

通过 CYCLONEDDS_URI 指定配置源，支持三种形态：

bash
# 本地文件（建议绝对路径）
export CYCLONEDDS_URI=file://$PWD/cyclonedds.xml

# 网络资源
export CYCLONEDDS_URI=https://example.com/configs/cyclonedds_prod.xml

# 内联 XML：URI 以 < 开头时按 XML 字符串解析
export CYCLONEDDS_URI="<CycloneDDS><Domain><General><AllowMulticast>false</AllowMulticast></General></Domain></CycloneDDS>"

URI 还支持 #fragment 追加片段。

未设置时的行为 ​

若未设置 CYCLONEDDS_URI，CycloneDDS 直接使用内置默认配置，不会自动去 /etc/cyclonedds.xml 之类的固定位置找文件。要用 XML 文件，必须显式设置该环境变量——这是"改了 /etc 下的配置却不生效"的常见原因。

代码指定（C API） ​

通过 dds_create_participant 一类 API 的配置参数可以覆盖全局配置。

XML 结构规范 ​

配置文件根元素为 <CycloneDDS>，声明命名空间与 Schema 位置可以在编辑器里获得智能提示与校验：

xml
<CycloneDDS xmlns="https://cdds.io/config"
            xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
            xsi:schemaLocation="https://cdds.io/config https://raw.githubusercontent.com/eclipse-cyclonedds/cyclonedds/master/etc/cyclonedds.xsd">
    <Domain id="any">
        <!-- 配置内容 -->
    </Domain>
</CycloneDDS>

核心配置模块 ​

完整参数列表与默认值以官方配置参考为准，以下只列常用项。

通用行为（<General>） ​

配置项 类型 说明 示例值
AllowMulticast 布尔/枚举 是否允许 UDP 多播。设为 false 强制单播，适用于受限网络 true, false, default
MaxMessageSize 整数+单位 单个 RTPS 消息最大大小，超出部分分片 65536B, 1MB
Transport 枚举 选择传输协议：udp/udp6/tcp/tcp6/raweth/fakeudp。用 TCP 设为 tcp 即可（旧的 <TCP><Enable> 已废弃） udp, tcp

注意两个容易写错的地方：

  • MaxRecvMessageSize（接收缓冲区最大消息大小）不在 <General> 下，实际位于 //CycloneDDS/Domain/Internal/MaxRecvMessageSize；
  • 不存在 EnableUDPTransmission、EnableTCPPort 这样的配置项，传输协议选择统一走 Transport。
xml
<General>
    <AllowMulticast>false</AllowMulticast>
    <MaxMessageSize>1MB</MaxMessageSize>
    <Transport>udp</Transport>
</General>

网络接口绑定（<General><Interfaces>） ​

多网卡环境下指定绑定哪个网卡。不存在独立的 <Network> 元素，接口配置统一在 Interfaces/NetworkInterface：

xml
<General>
    <Interfaces>
        <!-- 按 name 或 address 指定；autodetermine="true" 时自动选择 -->
        <NetworkInterface name="eth0" priority="10"/>
        <!-- 也可以按地址 -->
        <NetworkInterface address="192.168.1.100"/>
    </Interfaces>
</General>

发现机制（<Discovery>） ​

控制节点间的发现方式，是跨子网或禁用多播环境下的关键配置：

  • Peers：显式指定对等节点地址，用于静态单播发现；
  • ParticipantIndex：固定内置端点 GUID 的索引；
  • MaxAutoPeerIndex：自动发现 peer 的最大索引值。
xml
<Discovery>
    <Peers>
        <Peer Address="192.168.1.20"/>
        <Peer Address="192.168.1.21"/>
    </Peers>
</Discovery>

共享内存 / 零拷贝（PubSubMessageExchange） ​

启用 iceoryx2 一类的 PSMX 插件（新版路径）。PSMX 接口元素也在 Interfaces 下，属性 type 指定插件类型，library 缺省为 psmx_TYPE（即 type="iox2" 时默认加载 psmx_iox2 库），config 传插件自己的参数（如 IOX2 的 INSTANCE_NAME、KEYED_TOPICS 等，具体见对应插件文档）：

xml
<General>
    <Interfaces>
        <PubSubMessageExchange type="iox2"/>
    </Interfaces>
</General>

日志与调试（<Tracing>） ​

xml
<Tracing>
    <OutputFile>/tmp/cyclonedds.log</OutputFile>
    <Verbosity>config</Verbosity>

Verbosity 常用值从粗到细：fatal、error、warning、config、info、debug、trace。排查配置问题时设为 config 以上，启动时日志会打印实际加载的配置摘要。

兼容性调整（<Compatibility>） ​

用于与其他 DDS 实现互操作：

  • AssumeRtiHasPmdEndpoints：假设 RTI 对端拥有 PMD 端点（处理 RTI 特有行为）；
  • StandardsConformance：标准遵循严格度（pedantic/strict/lax）。

综合配置示例 ​

生产环境常见组合：禁用多播、静态 peer 发现、指定网卡、启用共享内存与日志：

xml
<CycloneDDS xmlns="https://cdds.io/config"
            xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
            xsi:schemaLocation="https://cdds.io/config https://raw.githubusercontent.com/eclipse-cyclonedds/cyclonedds/master/etc/cyclonedds.xsd">
    <Domain id="any">
        <General>
            <AllowMulticast>false</AllowMulticast>
            <MaxMessageSize>2MB</MaxMessageSize>
            <Interfaces>
                <NetworkInterface address="192.168.10.50"/>
                <PubSubMessageExchange type="iox2"/>
            </Interfaces>
        </General>
        <Discovery>
            <Peers>
                <Peer Address="192.168.10.51"/>
                <Peer Address="192.168.10.52"/>
            </Peers>
        </Discovery>
        <Tracing>
            <OutputFile>/var/log/cyclonedds.log</OutputFile>
            <Verbosity>info</Verbosity>
        </Tracing>
        <Internal>
            <MaxRecvMessageSize>2MB</MaxRecvMessageSize>
        </Internal>
    </Domain>
</CycloneDDS>

调试与验证 ​

语法验证 ​

用 xmllint 对照官方 XSD 校验：

bash
xmllint --noout --schema https://raw.githubusercontent.com/eclipse-cyclonedds/cyclonedds/master/etc/cyclonedds.xsd cyclonedds.xml
1

输出 cyclonedds.xml validates 即格式正确。

确认配置被加载 ​

把 <Verbosity> 设为 config 或更高，启动后检查日志开头的配置摘要（多播状态、网卡、共享内存等）。

共享内存生效验证 ​

  • 日志检查：info 级以上搜 "Iceoryx"、"SHM" 关键字，确认初始化成功；
  • 文件系统检查：ls /dev/shm | grep iox，存在 iox_ 开头的文件说明共享内存段已创建；
  • 网络抓包：同机跑发布/订阅端，tcpdump 监听端口——共享内存生效时数据面流量应消失，只剩少量发现流量。

常见问题 ​

  • XML 解析失败：检查标签闭合、属性引号、命名空间声明；
  • 配置不生效：确认 CYCLONEDDS_URI 在进程启动前已导出（ROS 2 环境下在 source setup.bash 之后设置）；确认没有指错文件——未设置该变量时不会自动找任何文件；
  • 共享内存无法启用：确认对应 PSMX 插件编译进了库（ldd your_app | grep -i iox），确认构建时打开了相应开关。

要点 ​

  • 配置入口只有 CYCLONEDDS_URI（或代码指定）：未设置时用内置默认，不存在默认路径查找。
  • 网卡绑定与 PSMX 插件都配置在 General/Interfaces 下；传输协议选择用 General/Transport，没有独立的 UDP/TCP 开关元素。
  • 排查配置问题的第一步是把 Tracing Verbosity 提到 config 级看启动日志——多数"配置不生效"是环境变量没导对。
